sa-13.1-100 libarchive 2026-10-31 Medium

libarchive 3.8.11 fixes several security issues, most of which can be triggered by processing a crafted archive. No CVEs have been assigned. A malformed ISO 9660 image with Joliet extensions could cause unbounded recursion and a crash, a crafted RAR archive could cause excessive memory allocation for a stored symbolic link, and a crafted XAR archive could trigger an integer overflow that caused its table of contents to be processed twice. When skipping stored entries in a streamed ZIP archive, file contents could be mistaken for the end of the entry, causing libarchive to interpret the rest of the archive differently from other tools. A memory leak when parsing ISO 9660 Rock Ridge entries was also fixed.

The XAR reader no longer cleans up the global libxml2 state, which could cause crashes or use-after-free errors in applications that also use libxml2 themselves. An integer overflow in wide string allocation that could lead to a heap buffer overflow on 32-bit systems, and a crash when an extended attribute changes while it is being read, were also fixed. In addition, bsdunzip no longer crashes when reading an archive from standard input. Update to libarchive-3.8.11 or later.

sa-13.1-099 libslirp 2026-10-31 Medium

libslirp 4.9.7 fixes several security issues that can be triggered by a guest using user-mode networking (for example, QEMU's user networking or rootless Podman containers). No CVEs have been assigned. The most serious is an out-of-bounds heap read in icmp_forward_error() that could disclose memory from the host process to the guest in ICMP error messages.

A guest could also crash the host process by corrupting the packet queue in if_output() when one connection generates a large amount of traffic, exhaust host memory by repeatedly sending IPv6 pings to the virtual gateway because of a memory leak, and add ARP or NDP entries for multicast addresses and for libslirp's own addresses. Update to libslirp-4.9.7 or later.

sa-13.1-098 fribidi 2026-10-31 Medium

fribidi 1.0.18 fixes several security issues that were found by an automated scan. No CVEs have been assigned. The most serious is an out-of-bounds write in fribidi_remove_bidi_marks() when the position maps returned by one call are passed to a later call. Text consisting of many back-to-back isolates, or of deeply nested isolates containing brackets, could also take quadratic time to process, allowing a denial of service in any application that uses fribidi (for example, through Pango) to display untrusted text.

Other fixes include an integer overflow in the run-pool allocation on 32-bit systems that could lead to a heap buffer overflow, crashes caused by unchecked memory allocations, an out-of-bounds read in the CapRTL decoder on platforms where char is unsigned, and stack buffer overflows in the fribidi and fribidi-caprtl2utf8 programs when producing UTF-8 output. This release also brings bidirectional text handling closer to the Unicode standard, which may change the output for unusual input. Update to fribidi-1.0.18 or later.

sa-13.1-097 aspell 2026-10-31 Medium

aspell 0.60.8.3 fixes four security vulnerabilities that can be triggered when processing crafted dictionary or word list files. CVE-2026-103658 is an integer overflow in String::reserve() that leads to a heap buffer overflow when loading a crafted compiled dictionary, which may allow arbitrary code execution. CVE-2026-75818 is a heap buffer overflow in prezip-bin when decompressing a crafted file, CVE-2026-75819 is an out-of-bounds read caused by unvalidated offsets in a compiled dictionary header, and CVE-2026-75820 is heap corruption caused by truncating the length of very long words in a personal word list. Several other memory safety problems in the handling of affix, character map, and phonetic data files were also fixed. Update to aspell-0.60.8.3 or later.

sa-13.1-096 libjpeg-turbo 2026-10-29 Medium

libjpeg-turbo-3.2.1 fixes several security vulnerabilities. A division by zero could occur when loading a non-grayscale indexed-color PNG image with an unspecified pixel format, causing a crash. A buffer overrun could occur when partially decompressing a crafted 4:2:0 JPEG image using merged upsampling and very small crop regions, and the RGB565 color converter could overrun its buffers when decompressing multiple scanlines at once. On 32-bit systems, an integer overflow could lead to a buffer overrun when loading packed-pixel images with more than 2^31 components. A use-after-free could occur when the same undersized destination buffer was used for multiple simultaneous transform operations. The TurboJPEG API was also hardened against reuse after a failed header decompression, which could lead to undersized buffers, and against applying one-pass quantization or RGB565 conversion to 12-bit JPEG images, which could overrun a color index array. If you use libjpeg-turbo, you should update to libjpeg-turbo-3.2.1. CVE-2026-75466.

sa-13.1-095 libheif 2026-10-29 High

libheif-1.23.7 fixes sixteen security vulnerabilities that can be triggered by processing a crafted HEIF or AVIF image. Fourteen of them are rated high by upstream. They include a heap buffer overflow when padding an image to an inconsistent size, a heap use-after-free when grid tiles are decoded in parallel (only in libheif-1.23.6), a use-after-free or double free caused by a stale handle in heif_context_encode_thumbnail(), an out-of-bounds read in the OpenH264 decoder plugin, and two ways to bypass the coded-size check in the AV1 decoding path. In addition, the gdk-pixbuf loader could crash on certain files, and the heif-dec and heif-info utilities mishandled some sample entries. If you use libheif, you should update to libheif-1.23.7 as soon as possible.

sa-13.1-092 libslirp 2026-10-29 Medium

libslirp-4.9.6 fixes several security issues that can be triggered by a guest virtual machine or container using user-mode networking. The ICMP echo reply length was not updated to match the data actually received, which could leak the host's real IP address to the guest under some conditions. The TFTP server did not check the space available in the reply buffer, completing the fix for a heap buffer overflow that could be triggered when the host is configured with a small interface MTU. The TFTP server could also read before the start of a buffer when given an empty filename. In addition, packets with invalid ("martian") addresses are now rejected. CVE-2026-115449, CVE-2026-95508.

sa-13.1-091 glib-networking 2026-10-29 Medium

glib-networking-2.90.1 fixes five security vulnerabilities. Three of them can affect BLFS systems built with the default GnuTLS backend: a remote TLS peer can cause unbounded memory growth by sending many TLS 1.3 session tickets, or by sending application data during the handshake, leading to a denial of service; and the client session cache key was not updated after a certificate property changed, which could allow resuming a stale TLS session. sa-13.1-090 samba 2026-10-29 High

Samba-4.25.1 fixes an access control bypass in the experimental vfs_ceph_rgw module, which was introduced in Samba-4.25.0. When a client opens an existing file using different letter case, the module fails to look up the file case-insensitively and treats the request as a file creation, skipping the access check. An authenticated user can use this to read or overwrite restricted files on shares that use vfs_ceph_rgw. This module requires Ceph libraries that are not part of BLFS, so BLFS installations are unlikely to be affected. Only Samba-4.25.0 is vulnerable. This update also fixes a crash in vfs_acl_xattr and a build failure on i686. CVE-2026-109411.

sa-13.1-089 python 2026-10-27 Medium

Python 3.15.2 contains several security fixes that are not present in Python 3.14.8. The most significant is a race condition in the cleanup of tempfile.TemporaryDirectory: an attacker who can modify the directory tree while it is being removed can replace a directory with a symbolic link, causing files outside of the temporary directory to be deleted or to have their permissions changed with the privileges of the process performing the cleanup.

Several issues in the tarfile module's extraction filters have also been fixed. When extracting a link fell back to extracting an archive member, the filter could be bypassed, and the tar filter did not reject link members that resolve to the destination directory itself. Additionally, http.cookiejar accepted cookies with a negative Version attribute without checking their domain against the request host, poplib did not reject control characters in POP3 commands, allowing command injection, and a buffer overflow could occur when resolving very long paths. The ssl module now also refuses certificate chains that contain compromised eMudhra intermediate CA keys.

If you use Python to process untrusted tar archives, HTTP cookies, or POP3 connections, or run Python programs that use temporary directories on multi-user systems, update to Python 3.15.2 or later. For more details, see CVE-2026-12345, CVE-2026-114583, and CVE-2026-115557.

sa-13.1-087 patch 2026-10-27 Medium

GNU patch 2.8.1 fixes a path-traversal vulnerability that allowed a crafted patch to create files outside of the source tree. When reverse-applying a patch that deletes a file, patch recreated that file without checking whether its pathname was safe, so an attacker who convinces a user or an automated workflow to apply a malicious patch in reverse could write to any location the user has write access to. This update also fixes a null pointer dereference and an infinite loop that could be triggered by malformed patches, and a symbolic-link resolution error that could cause patch to modify the wrong file. sa-13.1-084 7zip 2026-10-23 Medium

7-Zip 26.05 fixes several security vulnerabilities, none of which have been assigned CVE numbers yet. sa-13.1-083 node 2026-10-23 High

Node.js 26.12.1 fixes nine security vulnerabilities in Node.js itself. The most serious are in TLS certificate hostname verification, where non-canonical IP address strings (such as octal or hexadecimal notation) and hostnames containing fullwidth Unicode digits could be matched against certificates issued for a different host, allowing a server to be impersonated (CVE-2026-106069, CVE-2026-105483, and CVE-2026-106072). In addition, DNS resolution truncated hostnames containing NUL characters, allowing a different name to be resolved than the one that was checked against an allowlist (CVE-2026-105482), and an HTTP keep-alive client could accept a response that a server wrote to an idle connection before the request was sent (CVE-2026-105481). Other fixes address repeated random values from crypto.randomUUID() and crypto.randomInt() in startup snapshots and single executable applications (CVE-2026-106074), disclosure of data from the wrong file position in ZipFile (CVE-2026-106070), and Permission Model bypasses through wildcard paths and fs.realpathSync() (CVE-2026-106071 and CVE-2026-106073).

The Node.js release also addresses a critical vulnerability in the Brotli decoder (CVE-2026-111497). Node.js as built in BLFS uses the system brotli library, so this issue is fixed by updating brotli to 1.2.1, which is required for this update. See advisory sa-13.1-082 for details.

The severity of these issues is High, and all users of Node.js should update to 26.12.1 and brotli to 1.2.1 as soon as possible.

sa-13.1-080 php 2026-10-23 Critical

PHP 8.5.12 fixes two critical vulnerabilities in the PHP core that allow unauthenticated remote code execution. When an out-of-memory condition occurred during request initialization, PHP could leave an incomplete request state behind that was later used during shutdown (CVE-2026-109618). In addition, a global state that pointed into request memory was not always cleared between requests, allowing a later request handled by the same worker process to trigger a use-after-free (CVE-2026-109619). Working exploits have been demonstrated over HTTP against PHP running under Apache with mod_php, and CVE-2026-109619 has also been exploited against PHP-FPM. There is no configuration workaround for either issue. This release also fixes many other memory safety issues, including several use-after-free conditions and heap buffer overflows in various extensions. The severity of these issues is Critical, and all users of PHP should update to 8.5.12 as soon as possible.

sa-13.1-079 c-ares 2026-10-23 Medium

c-ares 1.34.9 fixes eleven security vulnerabilities, none of which have been assigned CVE numbers. sa-13.1-075 xorg-libraries 2026-10-23 Medium

Updates to five X.Org client libraries fix 17 security vulnerabilities. libfuse 3.18.3 (September 9, 2026) addresses a cluster of security issues, none of which have CVE identifiers assigned. sa-13.1-013 libxml2 2026-09-09 High

libxml2 2.15.4 addresses a single security issue, CVE-2026-86138, an integer overflow leading to a heap-based buffer overflow in the xmlDictAddQString function in dict.c. This function is part of libxml2's internal string-dictionary subsystem, used to intern qualified (prefix:local) names encountered while parsing XML. Because buffer-size calculations for these interned strings were not properly checked for overflow, a specially crafted XML document could trigger an undersized allocation followed by an out-of-bounds heap write, resulting in memory corruption. sa-13.1-010 net-dns 2026-09-09 High

Net::DNS 1.57 fixes CVE-2026-81928, a memory-exhaustion denial-of-service caused by unbounded recursion in Net::DNS::RR::TSIG::sig_data(). When re-encoding a previously decoded message, sig_data strips TSIG records only from the additional section; a TSIG record placed in the answer or authority section survives and is signed again, causing encoding to recurse into itself with no termination condition. The decoder detects such a misplaced TSIG and logs a "misplaced or corrupt TSIG" warning, but does not reject the message as RFC 8945 §5.2 requires, leaving the malformed record in place. The bug triggers only when the TSIG carries an empty MAC and only in code that re-encodes a decoded message, such as a DNS forwarder or proxy; each recursive cycle re-encodes the whole message, so under 100 bytes on the wire can exhaust available memory and crash the process.

Note that two other recent CVEs sometimes associated with Net::DNS — an eval-injection flaw in EDNS EXTENDED-ERROR parsing and a stack-exhaustion DoS via chained compression pointers — were already resolved in the prior 1.56 release, not in 1.57.

sa-13.1-002 uri 2026-09-08 Medium

URI 5.36 (released 2026-08-19) fixes a single security issue, CVE-2026-19953. The module's internal URI::_idna nameprep routine lowercased hostname labels but never applied Unicode Normalization Form C (NFC) before punycode encoding, even though RFC 5891 requires NFC normalization prior to IDNA A-label conversion.

As a result, a hostname label that wasn't already in NFC could be encoded to a non-standard A-label that differs from — and doesn't round-trip to — the label a spec-compliant client would produce. For example, a precomposed Devanagari sequence encoded to xn--72b5c without normalization but to xn--11b2fg with it.

This is a host-confusion vulnerability: code that extracts host() from a URI object built from untrusted input and uses it for security decisions (allow/deny lists, SSRF filters, cache keys, deduplication) could see a different host value than what an RFC-compliant HTTP client or resolver would actually contact — enabling filter bypass or SSRF.

The fix applies proper NFC normalization in nameprep before A-label generation, aligning URI's host encoding with standard IDNA behavior.
