## What was found

The gate without a reference, run on the three seeds' held-out answers, shows 56 problems and 44 are right by the
specification check (79%). Read by hand, most of the 12 it "gets wrong" are faults in the check's reference
solutions, not in the answers: MBPP's own solution for problem 605 ("check if the given integer is a prime
number") returns after testing only the divisor 2, so it calls 9 prime; for 454 ("a word containing 'z'") it
requires a character after the z; for 891 ("same number of digits") it divides with floats. EvalPlus found and
corrected such solutions: MBPP+ (Liu et al., "Is Your Code Generated by ChatGPT Really Correct?", arXiv:2305.01210;
huggingface.co/datasets/evalplus/mbppplus, Apache-2.0, 378 tasks) replaces 605's with a true primality test and
454's with `'z' in text`, and leaves out several ill-posed tasks (891, 665, 680 and 768 are not in it).

## The change

`t/spec_check.py --reference-plus FILE`: for an MBPP problem that MBPP+ holds, with the same function name, the
check runs MBPP+'s solution in place of the original. Every other problem, and every HumanEval and APPS problem,
keeps its reference. Nothing else in the check changes.

## How it is applied

Every held-out set on record is re-scored both ways, with the same rule, and both numbers are reported: the
student's three seeds and Phi-4-mini's seventeen prompted sets (and, when it is graded, Phi under the grammar).
The original numbers stay in their registrations; this file records the second count.
