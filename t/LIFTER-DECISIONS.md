# Lifter decisions

The four designs in `t/lifter-design/` (DPN: dafny-print-normalised, RD:
recursive-descent, TSG: two-stage-generic, VL: verified-lift) each end with an
"open decisions" section. Read together they name the same questions, and
each states what reversing its default costs. This file settles them so the
implementers have one answer per question. Row 1 was decided by Treston on
2026-09-05; the rest are the majority default across the four designs, with
the ROADMAP.md "assumed" list (WS-16 notes) breaking ties, approved with the
implementation plan on 2026-09-05. A row is reversed by editing this file and
re-running the corpus; the sidecar records which rule fired, so every count
can be re-derived under the other choice.

Every rewrite is recorded in the task's `.lift.json` sidecar under the name in
the "chosen" column, so the disagreement table can say which rule a row rests
on.

| 22 | Array mutation and allocation: `a[i] := e`, `new int[n]`, a method that `modifies` an array, a method returning one it allocated | n/a (t had no seq mutation at design time) | n/a | n/a | n/a | An `array<int>`/`array<nat>` parameter or local is a `seq` value (SPEC.md "Sequences as values (v1)", 2026-09-09); `a[i] := e` becomes `a := a[i := e]` (`{"op": "update", ...}`); `new int[n]`/`new nat[n]` becomes `seq(n, 0)` (`{"op": "fill", "args": [n, {"int": 0}]}`); `a.Length` is `len(a)`, unchanged from decision 1. Two shapes map, at most one mutated/allocated array per method: (a) **modifies-param** -- a method with ZERO Dafny-declared returns that `modifies` exactly one array parameter and writes `a[i] := e` somewhere becomes a task with `a` as a `seq` parameter and a FRESH `seq` return (named `<a>_out`, collision-checked by the same renamer as every other name); the body is primed `<ret> := a;` so every later `a[i] := e` becomes an update of the return; `old(a[k])` and `old(a[..])` (whole-array, unbounded) read as the PARAMETER's own value, and every other (non-`old`) reference to `a` in the body or ensures reads as the return's value, matching what Dafny's own heap semantics already mean by the one identifier `a`. A method that ALREADY returns something (BubbleSort's own `n`, removeElement's own `i`) is refused instead (`modifies-with-existing-return`): it would need a SECOND return, and t has exactly one. (b) **alloc-fill** -- the return itself (`squared := new int[a.Length]`) or a local later copied to it (`var cubedArray := new int[a.Length]; ...; return cubedArray;`) becomes a seq return; `fresh(b)` on it is dropped (SPEC.md), on both sides of the checker's equivalence lemma (`_strip_fresh_conjuncts`/`_strip_fresh_src`) since an arbitrary lemma parameter is not something Dafny evaluates `fresh()` on the way it would the method that actually allocated `b`. A `seq`'s length is not automatically invariant across a loop the way a real array's `.Length` is (Dafny's own well-definedness rule -- "each ensures/invariant clause may assume only requires/earlier clauses", never what the body's loop separately proved -- SPEC.md's Definedness section, the same rule t itself states): `len(<ret>) == <the array's own fixed length>` is added as the task's own FIRST ensures clause (`array-length-return-ensures`) and PREPENDED (not appended, unlike decision 5's `nat-invariant-added`) to every loop invariant list that touches the mutated seq (`array-length-invariant-added`); the same fact, granted via `requires`, keeps the checker's `L_ens`/`L_inv`/`L_dec` lemmas provable despite this asymmetry the source never has to state. Recorded `array-mutation-as-seq`, `array-new-as-fill`, `array-elem-assign-as-update`. What stays refused, `array` (the array's own type is wrong) or `array-mutation` (the mutation shape is wrong): two-dimensional arrays (`array2`/`array3`), arrays of non-int/non-nat elements, `multiset` over a mutated array's slice (Clover_bubble_sort's `multiset(a[..])==multiset(old(a[..]))`), a bounded slice `a[lo..hi]` (still `seq-slice`; only the unbounded `a[..]` on the mutated array is accepted), more than one mutated array per method, a mutated array also passed to another call (aliasing, this shim cannot verify past it), any `modifies` naming anything but the one array, and any shape not named above. Measured first on the 785 DafnyBench programs (own regex + `coverage_census.py`, 2026-09-09): 308 use an array (census `array` boolean, pre-row-22), 152 assign an element (`array-mutation`), of which (file-level, so Main's own unrelated `new` counts against the file, not the method) 71 mutate a parameter in place under `modifies` alone, 47 allocate-and-fill alone, 34 do both somewhere in the file (usually Main plus the graded method, not one method doing both -- row 22 refuses that as `multi-array-mutation` if it ever is). Of the 785, 105 have gaps that are now entirely subsumed by this row (`array`, `array-mutation`, `seq-return`, `zero-returns`, alone or combined): 57 read-only-array-only (decision 1's own territory, 11 already lifted before this row, the rest refused for OTHER reasons this row does not touch -- `heap`/null-checks, `unbounded-quantifier`, `function-contract`), 18 `array`+`array-mutation` (this row's direct target: allocate-fill mostly, e.g. `dafny-synthesis_task_id_8` SquareElements), 28 `array`+`array-mutation`+`zero-returns` (the `modifies`-param shape's direct target, e.g. Clover_double_array_elements/replace/swap_in_array), 2 `zero-returns` alone (unrelated to arrays, untouched by this row). Verified end to end (checker lemmas AND the differential harness) on Clover_array_product (alloc-fill, two read-only params), Clover_double_array_elements and Clover_replace (`modifies`-param, zero return, point-wise `old`). `lift_check.py`'s `_t_expr` renders `update`/`fill` back as `s[i := v]`/`seq(n, _ => 0)`; `_split_array_post_state` rewrites the SOURCE ensures/invariant AST (never `_print_expr` itself) so a non-`old` occurrence of the mutated array's one Dafny identifier prints as the return while an `old`-wrapped one is left alone to print as the parameter, since Dafny repeats that one identifier for both and a flat rename dict cannot tell them apart; the differential harness compares `arr{j}[..]` (the materialised argument array, post-call) or `srcv[..]` against the lifted `seq` result, and `_POINT_RE`/`_dafny_value_matches` now parse a bracketed `[1, 2, 3]`-shaped printed value (measured: `dafny run`'s own seq print format, spaces after every comma, broke the old `\S+`-per-field parser -- the first tasks through this harness with a seq-typed RESULT rather than only seq-typed arguments). Decided 2026-09-09, once SPEC.md's "Sequences as values (v1)" opened the gate. | Refuse `array-mutation`/re-widen `array` as before: 152 of the 785 (`array-mutation` true) stay out of the fragment on that gap alone, 308 in total lose the read-only row too if `array` reverts to unconditional refusal (decision 1's own row, not this one, but the two share one census boolean's worth of history); the 46 programs whose ONLY remaining gap this row closes (18 + 28 above) stay refused. |

Excluded on purpose: the ROADMAP 12.3 question, whether a task with no
refuting twin is refused, stays open and is not the lifter's to settle. The
lifter emits the task and records the twin refusal; the count treats it under
whatever 12.3 decides.

Where a design's default was reversed by this file, the design text still
argues the other way: VL section 15 items 1 and 5 (arrays, clause splitting)
