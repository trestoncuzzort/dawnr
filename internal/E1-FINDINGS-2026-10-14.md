## What was measured, and on which population

Two distinct populations, kept separate on purpose:

1. **The 426 archived real/twin pairs** (`t/twins/pairs`), run through the AUTHENTIC paired grounded-witness
   gate (`verifiers.cell_pair` at flake n=3; the twin lowered WITH its grounded witness as the kernel's
   `t_refutation_certificate`, a goal the kernel must PROVE — a genuine REFUTED, not a body-only UNPROVED).
   **Ascertainment:** these pairs were SELECTED for all-seven real-verification AND all-seven twin-refutation
   (`twins_artifact.py`). So this is a CURATED REPRODUCIBILITY / adequacy population. The curve below measures
   whether the recorded all-seven verdicts REPRODUCE under an independent, hash-bound re-run — it is NOT an
   unbiased correctness or false-accept base rate.

2. **The direct-body corpora mutant matrix** (11,088 fully-adjudicated cells over HumanEval/auto/Vericoding/
   DafnyBench, `audit._kernel_verdict`) — the broader-benchmark evidence, reported separately with its own
   recipe (see "Still open"). There a survivor a kernel verifies has UNKNOWN intended-correctness (spec-gap vs
   spec-permitted is not adjudicated), so it is a survivor-VERIFICATION RATE, never an "accuracy": real coverage
   95.1%→43.8% and survivor-verified-rate 72.5%→17.6% across k=1..7. `k` there is an experimental cross-kernel
   AGREEMENT vote, NOT `T_MIN_KERNELS` (an availability floor), and the direct-body path reads a wrong body as
   UNPROVED, not refuted — labelled as such.

## Engine-first Frama-C fix (what moved k7 from 0% to 96%)

The raw-v1 (pre-fix) curve was k1..5=426, k6=423, **k7=0** — Frama-C refuted no twin. A measured ADAPTER bug,
not a gate failure: (1) `_cert_states_negation` recognised only ASCII `!`/`\false`, but Frama-C's `-print`
normalises `!` → U+00AC `¬` (all unproved twins); (2) `_UNREACHABLE_SMOKE` rejected the real `_s<N>` dead-code
smoke suffix, miscalling a smoke failure as vacuity. Fixed ENGINE-FIRST on an isolated clone of upstream
`18d79ef` via a clean THREE-WAY merge (pin `d13d11d0` base + dawnr cert-negation hardening + upstream's 292-line
`lower_framac` review fixes — both preserved), then two narrow fixes with positive + forgery controls (named
tautology / spoofed function name still rejected — fail-closed), adapter at SHA `ca6ee4d6159c`. Measured
before/after on real Frama-C; four persistent regression tests committed at `7271e2e`. Two further real-kernel
(no-mock) negative controls were retained: a SEPARATE-function negated-clause case → UNPROVED (isolates the
negation guard from other gates), and `f_wp_smoke_dead_code_s18` with `requires 0==1` → VACUOUS (a class-looking
function name cannot launder default-requires smoke).

The distinct whole-Frama-C TASK-column agreement check (baseline `18d79ef` vs patched `7271e2e`, 114 committed
tasks, isolated snapshots) is run SEPARATELY; baseline is complete (114/114 structured verdicts, 72 graded + 42
named lowering abstentions), the patched run is in progress, and NO whole-column pass is claimed until it
finishes and every changed cell is read.

## Replayable certificates

Every one of the 2982 verdicts carries a run-backed `paired-observation` certificate (in-toto Statement v1)
that the user's own `dawnr check` replays with NO model: it recomputes the pair identity from the embedded
real/twin/witness; recomputes `eff_config` AND the FULL `base_config` (flake / SPARK prover / kernel versions /
engine+harness source hashes) to their ids, with `eff_config.base == manifest_config_id`; binds the recorded
full Result to the FRESHLY observed one (backend / backend_version / source_sha256 / outcome / ok / budget —
wall_ms excluded as provenance); applies the hash-bound flake policy and the per-cell SPARK policy taken from
`Result.extras.gnatprove_jobs` (NOT the worker-env-update dict); and binds the recorded lowered-source digests
to a re-lowering. A changed lowering, a tampered outcome/source/version/budget/policy, or a malformed provenance
block makes `dawnr check` fail or go undecided. Cells with no admissible stable observation get an explicit
`observation-record-only` certificate (UNDECIDED with reason), never an empty-denominator success.

Each certificate also retains a concrete `run_ref` (manifest + checkpoint + canonical-record digests) so
identical-config runs are distinguishable; this is informational provenance, not an authenticated-history claim.
The published bundle index is public-safe (run basename + identifying digests, no home path).

**Scope of the replay claim, stated precisely:** the 2982 certificates were MINTED and verified by (a) full-set
STRUCTURAL validation of all 2982 against the frozen checkpoint/manifest/Result objects (0 mismatches) and (b)
12 representative ACTUAL native `dawnr check` replays through real kernels — one all-seven-accepted pair plus
the Lean-unproved / Rocq-unproved / Frama-C-vacuous cases — which reproduced the recorded observations. This is
observation reproduction and full-set structural validation; it is NOT 2982 executed kernel replays, and
unproved/vacuous observations are reproduced AS unproved/vacuous, never turned into proofs.

## A recording caveat for the NEXT runner (frozen v2 unchanged)

`run_par.spark_jobs_env()` returns worker-env UPDATES, not the complete effective SPARK policy: with an
inherited `T_SPARK_JOBS` it returns `{}`, so `eff_config_id` does not capture an inherited setting and a resume
under a different inherited value can reuse stale results. This did NOT affect the two frozen runs — every one of
their 852 source-side SPARK Results recorded `extras.gnatprove_jobs == 1`, and both `runmeta.spark_env` are
explicitly `{'T_SPARK_JOBS':'1'}`. The fix (distinguish worker-env updates from the normalized effective policy
and bind THAT to config/reuse) belongs to the next runner version; the frozen v2 script/manifest are NOT edited
to pretend the old run captured more than it did. Certificates already treat an empty env-update as unknown
(never jobs=1) and bind the per-cell policy from `Result.extras`.

## The direct-body matrix recipe (distinct from the paired gate; built 2026-10-14)

The 11,088-cell direct-body matrix (vcd 5929 + df 4361 + hev 616 + auto 182) is adjudicated BODY-ONLY
(`audit._kernel_verdict`, no grounded-witness substitution): a kernel reads a wrong body as UNPROVED, never a
grounded REFUTED, and a survivor it verifies has UNKNOWN intended-correctness — a survivor-VERIFICATION rate,
not an accuracy. The historical record is STATE-ONLY: `{path, which, kernel, config_id, config, src_hash
(task-AST hash), state, raw}`, with NO full Result, NO lowered-source digest, NO flake flags, under a Dafny/Z3/
SPARK + engine-pin/harness config (`1e3a19aaf14c`, engine `d13d11d01f8f`) — not the newer paired config.

Its certificate (`db_certificate.py`, predicate `urn:dawnr:direct-body-observation:v1`) binds ONLY what was

hash, and for a survivor the frozen body + bodyhash), invents no historical Result/digest/flag, and on
`dawnr check` reloads the task from its corpus path, confirms `canon(task)==src_hash` (and `canon(body)==
bodyhash`), re-lowers the BODY ONLY and re-adjudicates, then compares the FRESH state to the recorded one. The
fresh Result metadata is a NEW observation under the CURRENT engine, reported as such and linked by identity; a
different engine than the recorded `engine_pin` makes a state match UNDECIDED (not a same-engine reproduction),
never silently reproduced.

Validated: `db_certificate.py --self-test` (REAL + survivor positives; recorded-state / src_hash / subject /
survivor-body tampers; source-changed; engine-mismatch→UNDECIDED; corpus-unavailable→UNDECIDED) and native
