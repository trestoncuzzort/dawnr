## 6. Traps that have cost hours here

1. **`pkill -f <pattern>` matches the shell running it.** Over ssh this kills the command halfway through while
   printing success. It left a vLLM server holding four shared cards for an hour and three quarters. Use a
   bracketed pattern (`pkill -f '[l]oop_generate'`) and put the kill in its own ssh call, because the launch
   half of a compound command carries the pattern too.
2. **Kernels need their PATH.** Without it Verus reads `verus ?` and every Verus cell comes back MALFORMED.
   Use `lab.KERNEL_PATH` (`~/.cargo/bin`, `~/.opam/default/bin`, `~/.elan/bin`, `~/.local/fstar/fstar/bin`,
   `~/.local/gnatprove/.../bin`, `~/.local/verus/verus-x86-linux`). t lab and `t/overnight.py` set it.
3. **A flag can reach three call sites and miss the one that runs.** `--grammar` was wired into
   `generate_samples`, but every held-out run takes the single-sample fast path that calls `model.generate`
   directly. The tell was that the "constrained" run had 158 parse failures against the unconstrained 159.
   Check a claim against a number that would move if it were true.
4. **A tokenizer can silently eat text.** DeepSeek-Prover-V2 loads as LlamaTokenizer under transformers 5.17
   and drops every space. `loop_generate` now round-trips a line of t before trusting it; keep that check.
5. **A grammar mask must be as wide as the logits.** xgrammar leaves anything past the mask unmasked; Phi's
   tokenizer is 200,032 against 200,064 logits, so 32 tokens were sampleable outside the grammar.
6. **`t/out/` is gitignored.** Results a reader is pointed at must be `git add -f`ed.
7. **A grading cell is not a fixed number of cores, so a fixed `--jobs` is the wrong control.** The measured
   rule from 2026-09-18 was 32 cells for this 120-core machine, at about 3.4 cores a cell. On 2026-09-19 the
   proof-trained model's answer set drew about **7 cores a cell** -- 24 cells plus four generation jobs took
   the machine to a load of 138 -- because the shape of the answers decides how much parallel prover work each
   cell spawns. Grading over the line is not merely slow: SPARK's wall backstop fires on cells that prove when
   run alone, and a timeout is not a verdict. So set `--jobs` by watching the load for a minute after the run
   starts, and lower it if the machine goes past its core count; 12 was right for that set while generation was
   also running.
8. **DPO memory.** trl 1.13 removed `use_logits_to_keep`, so the policy forward builds full-window logits:
   3,072 is the window that fits a 1.5B on 16 GB and keeps 482 of 489 pairs; 2,560 silently keeps 45.

## 7. An audit on 2026-09-19, and what it changed

Zooming out at the end of the session found six things nobody had noticed. They are fixed; they are recorded
here because each one is the kind of thing that silently makes a number wrong.

1. **A column said "checked" when nothing had checked it.** `score_heldout.py` counted an answer as
   specification-checked whenever it was *absent* from the disagreement list, so an answer set nobody had ever
   run `spec_check.py` over scored full marks. This produced a false claim in this project's own reporting:
   round 5's student was described as 3 clean surviving the check against Phi's 2, "one ahead". Checked
   properly it is **2 against 2**, a tie. `spec_check.py` now records which tags it ran over and merges with
   earlier runs; `score_heldout.py` prints `not checked` for anything else. All ten held-out rows have since
   been checked: 86 clean answers, 67 agree, 8 disagree, 11 uncheckable.
2. **The leak check named files instead of globbing them**, so round 6's pool sat for a day without anyone
   confirming it held no held-out problem. It now checks every `sft-*.jsonl` and `pairs-*.jsonl` — eight files,
   all clean — and cannot fall behind a round again.
3. **A clean count from a partial grading looked like a full one.** A table graded with `--kernels lean` alone
   would report "clean" for agreement among one column, with the column count four columns away. The cell now
   says `(only N kernels)` when N < 7.
4. **The table did not carry the number the project steers by.** Conversion — test-passing answers the seven
   can prove — had to be recomputed by hand every time. It is a column now.
5. **The runner identified a step by its script.** A dozen steps run `spec_experiment.py`; one running made
   them all read as running, which is why `t/overnight.py` once reported `preflight` running while nothing was
   and stopped a night early. It now matches the script *and* what names the step's own output.
6. **A round's data was not in the repository.** A clone could read that round 6 scored 3 clean and could not
   rebuild the pool behind it. The 87-example pool, the 648 pairs, pool v5's split and both id lists are now
   tracked (7 MB). Weights are not: they follow from these plus section 4.

Two smaller ones: `email_founders.py` was untracked but one `git add -A` from being committed, so it joined the
personal drafts in `.gitignore`; and a `grade_lab.sh` shell had been idle for 21 hours and was killed.

Also added to the README's limits, because someone will raise both: the 232 held-out problems are MBPP, which
every base model here was almost certainly pretrained on — the split stops this project's training leaking into
its own evaluation and cannot stop a model having met MBPP before we did, which applies to every row equally;
and the prover's 6 against Phi's 3 is 7B against 3.8B, so it is not a per-parameter claim.
