## 1. Where the project actually stands

The goal is a small model, trained here, that beats Phi-4-mini on 232 held-out problems, where an answer counts
only if its tests pass, all seven proof systems verify it, and all seven refute a deliberately broken twin.

**Three rounds have tied Phi at 3 clean of 232.** Rounds 4, 5 and 6 used three different data recipes -- more
problems, more answers, then preference pairs aimed at the gate the student loses at -- and none moved the
count. `t/out/score-r6.md` is the table; `README.md` leads with this.

Two things measured on 2026-09-18 change what to try next.

**The gate is the proof, not the notation.** Round 6's student wrote 36 well-formed answers to Phi's 12 and 9
test-passing to Phi's 6, then converted 3 of 9 into clean answers where Phi converted 3 of 6. Writing t is not
the problem; writing a specification the seven can discharge is.

**A proof-pretrained model converts better than anything else here.** `DeepSeek-Prover-V2-7B`, prompted, never
fine-tuned by us: 39 well formed, 10 test-passing, **6 clean**, conversion 6 of 10, and none of its six
specifications disagreed with its problem under `t/spec_check.py` (Phi loses one of three to that check). It is
the first result here that points at a fix rather than closing a door, and the fix it points at is the base
model. It is three answers wide and needs seeds before it is a claim.

**Constrained decoding works and is not enough.** With `--grammar t/t.gbnf` the round 6 student's parse
failures fell from 159 of 232 to 44, well-formed answers rose 36 to 58, test-passing 9 to 14, and clean 3 to
**4**. Phi under the same constraint is still generating; until that finishes, 4 against 3 is not a comparison,
because a constraint applied to one side only is two experiments.

## 4. The pipeline, command by command

    # generate (any model, any id list)
    ~/.venv-vllm/bin/python t/loop_generate.py --adapter none --base <hf-id> --tag <tag> \
        --pool v3 --prompt v3 --ids-file t/out/loop/eval-ids.txt [--grammar t/t.gbnf] [--max-new N]
    # or, for a model served by an OpenAI-shaped API (vLLM):
    python3 t/spec_experiment.py generate --model <name> --tag <tag> --pool v5 --api openai \
        --host 127.0.0.1:8077 [--grammar t/t.gbnf]

    python3 t/spec_experiment.py extract --model <tag> --pool v3     # replies -> t tasks
    python3 t/spec_experiment.py tests   --model <tag> --pool v3     # run each task's own tests
    python3 t/pool_pick.py t/out/spec-experiment/<tag> --control 40  # TRAINING sets only: filter + control
    # grade (held-out sets have no grade-in; they are graded whole, which is the point of a held-out set)
    python3 t/run_par.py --jobs 32 --tasks t/out/spec-experiment/<tag>/tasks \
        --out /dev/shm/tup-grade/<tag>/kernels --table t/out/spec-experiment/<tag>/kernels.md

    python3 t/spec_check.py --pool v3 --only clean <tag>             # do the specs mean the problem?
    python3 t/loop_dataset.py --from-samples <tags...> --split t/out/loop/split-v5.json \
        --min-kernels 7 --out-suffix r7                             # the pool and the pairs
    PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True ~/.venv-vllm/bin/python t/loop_train.py \
        --sft t/out/loop/sft-r7.jsonl --pairs t/out/loop/pairs-r7.jsonl --sft-first --max-len 3072 \
        --out t/out/loop/adapter-r7
    python3 t/score_heldout.py <tags...>                            # the table

`python3 t/preflight.py` refuses to let a round start on a checker whose version cannot be read, a held-out
problem in a training set, a clean answer resting on a flake or timeout, or a spec that disagrees with its
problem. Run it with the kernels on PATH (see section 6) or it will fail on `verus ?`, which is the trap it
exists for.

`python3 t/lab.py` opens the window. It **watches only** -- the Run buttons were removed on purpose, because a
button that starts a second copy of a running step loses a night's work. Steps are driven from a terminal.

## 6. Traps that have cost hours here

1. **`pkill -f <pattern>` matches the shell running it.** Over ssh this kills the command halfway through while
   printing success. It left a vLLM server holding four shared cards for an hour and three quarters. Use a
   bracketed pattern (`pkill -f '[l]oop_generate'`) and put the kill in its own ssh call, because the launch
   half of a compound command carries the pattern too.
2. **Kernels need their PATH.** Without it Verus reads `verus ?` and every Verus cell comes back MALFORMED.
   Use `lab.KERNEL_PATH` (`~/.cargo/bin`, `~/.opam/default/bin`, `~/.elan/bin`, `~/.local/fstar/fstar/bin`,
   `~/.local/gnatprove/.../bin`, `~/.local/verus/verus-x86-linux`). t lab and `t/overnight.py` set it.
3. **A flag can reach three call sites and miss the one that runs.** `--grammar` was wired into
   `generate_samples`, but every held-out run takes the single-sample fast path that calls `model.generate`
   directly. The tell was that the "constrained" run had 158 parse failures against the unconstrained 159.
   Check a claim against a number that would move if it were true.
4. **A tokenizer can silently eat text.** DeepSeek-Prover-V2 loads as LlamaTokenizer under transformers 5.17
   and drops every space. `loop_generate` now round-trips a line of t before trusting it; keep that check.
5. **A grammar mask must be as wide as the logits.** xgrammar leaves anything past the mask unmasked; Phi's
   tokenizer is 200,032 against 200,064 logits, so 32 tokens were sampleable outside the grammar.
6. **`t/out/` is gitignored.** Results a reader is pointed at must be `git add -f`ed.
7. **DPO memory.** trl 1.13 removed `use_logits_to_keep`, so the policy forward builds full-window logits:
   3,072 is the window that fits a 1.5B on 16 GB and keeps 482 of 489 pairs; 2,560 silently keeps 45.
