# Teacher scout: open-weight teachers for Dafny, Verus and Lean specifications

- Date (UTC): 2026-10-21. Searches started 08:31 UTC; tables assembled 09:17 UTC.
- Method:
  - arXiv API over HTTPS with curl, Atom parsed by python3 -I and xml.etree: 50 queries, 3 s apart, 15 results each. 530 rows, 399 distinct ids. One id_list call returned 59 abstracts. Later id_list calls returned HTTP 429 or 503, so entries 24 and 120 (found only by WebSearch) take the title from the search result and the year from the id.
  - WebSearch, standard mode: 13 queries. WebFetch: 7 calls, 4 returned licence text (DeepSeek, Qwen, Gemma, and a Mozilla copy of the Llama 3.1 licence); the other 3 were redirects or 404s on Meta and Llama URLs.
  - gh search repos: 96 saved queries plus 6 probes, 2 s apart, no 403 or 429 seen. 30 of the first 56 saved queries were multi-word phrases that returned nothing, so 40 short queries were added. 470 rows, 436 distinct repositories. Last update is pushedAt. Licence is gh's licence key (lowercase, SPDX-style); unknown where gh reports none, other where gh reports Other.
  - Hugging Face API: 30 model searches and 12 GGUF name searches, plus 3 probe or detail calls; 32 model-card README fetches (31 returned text). No model weights were downloaded or cloned.
  - Numbers in the why cells come from abstracts read this session. The top-15 section labels each number as paper abstract, model card table, or search summary.
- Issue key: T1 open-weight models or papers writing Dafny, Verus, Lean, Rocq, F*, ACSL, JML, TLA+ or similar specifications and proofs; T2 measured comparisons on specification synthesis or verified-code benchmarks; T3 teacher-student or verification data pipelines with filters; T4 running larger open models on one 16 GB card (quantisation, MoE offload, speculative decoding, KV cache); T5 licence facts on training with model outputs.

## Top 15 teachers to try first

Ranking basis: fit in 16 GB first, then a permissive licence with a GGUF build, then the strongest number seen. Fit sizes are estimates from parameter counts unless stated. Lean provers write Lean rather than Dafny-style specifications, so they rank as proof-side helpers. The clearest open-model Dafny measurement in these sources is the ATLAS fine-tune (entry 96).

Number sources: "paper abstract" is an arXiv abstract read this session; "model card table" is a README table read by column position; "search summary" is a WebSearch snippet that was not read in full.

1. Qwen/Qwen2.5-Coder-7B-Instruct (entry 232). 7.6B. Q8_0 fits fully (estimate). Apache-2.0; official GGUF. Best number: 56.9% on DafnyBench after the ATLAS fine-tune, up from 32.4% (entry 96, paper abstract). The abstract says "Qwen 2.5 7B Coder" and does not name the checkpoint.
2. Qwen/Qwen2.5-Coder-14B-Instruct (entry 231). 14.8B. Q6_K fits fully (estimate). Apache-2.0; official GGUF. No verified number seen. A reseller page gives 82.1% HumanEval (search summary, unverified). The technical report (entry 116) is the place to confirm it.
3. Qwen/Qwen3-Coder-30B-A3B-Instruct (entry 228). 30.5B MoE with 3B active. Q4_K_M needs partial expert offload on 16 GB (estimate; a search summary puts the file near 19 GB). Apache-2.0, LICENSE fetched. Best number: 60.4% SWE-bench Verified, relayed by llmrun.dev (search summary). Another summary gives 51.6 under a different model name, so the official card figure is unconfirmed. No RTX 4080 tokens-per-second figure was found.
4. Goedel-LM/Goedel-Prover-V2-8B (entry 201). 8.2B. Q8_0 fits (estimate). Apache-2.0; GGUF by mradermacher. Best number: 84.6% pass@32 on miniF2F (entry 39, paper abstract). The model card states 83.0% (entry 201), so the two sources disagree.
5. Pythagoras-LM/Pythagoras-Prover-4B (entry 207). 4.4B. Q8_0 fits (estimate). Apache-2.0; GGUF by tinyopsec. Best number: 86.1% pass@32 on miniF2F-test (entry 40, paper abstract; the card gives 86.07%).
6. Goedel-LM/Goedel-Code-Prover-8B (entry 203). 8.2B. Q8_0 fits (estimate). Apache-2.0; GGUF by mradermacher. Best number: 62.0% prove success over 427 Lean code-verification tasks (entry 38, paper abstract).
7. AI-MO/Kimina-Prover-Distill-8B (entry 210). 8.2B. Q8_0 fits (estimate). Apache-2.0; GGUF by gabriellarson. No benchmark number for this checkpoint was seen. The 80.7% pass@8192 miniF2F figure is for the headline model of the Kimina-Prover Preview paper (entry 36, paper abstract), whose size the abstract does not name.
8. Qwen/Qwen3.5-9B (entry 235). 9.7B. Q8_0 fits (estimate). Apache-2.0; GGUF by unsloth. Best number: 65.6 on LiveCodeBench v6 (model card table, column read by position).
9. Qwen/Qwen3.5-35B-A3B (entry 237). 36.0B MoE with 3B active. Q4 with expert offload (estimate). Apache-2.0; GGUF by unsloth. Best number: 69.2 on SWE-bench Verified (model card table, column read by position).
10. microsoft/phi-4 (entry 240). 14.7B. Q6_K fits (estimate). MIT; official GGUF repo. Best number: 82.6 HumanEval (model card table, phi-4 column).
11. deepseek-ai/DeepSeek-Coder-V2-Lite-Instruct (entry 238). 15.7B MoE. Q4_K_M or Q5 fits (estimate). DeepSeek Model Agreement (licence tag other). This is the previous teacher. The card text gives no benchmark number.
12. mistralai/Devstral-Small-2-24B-Instruct-2512 (entry 243). 24.0B. Q4_K_M with partial offload (estimate). Apache-2.0; GGUF by unsloth. Best number: 68.0% SWE-bench Verified from the Mistral launch post (search summary).
13. 8F-ai/Verus-R1 (entry 223). 2.2B, derived from Qwen3.5-2B. Q8_0 fits (estimate). Apache-2.0; GGUF by mradermacher. Verus-focused. The card gives no benchmark number.
14. ByteDance-Seed/Seed-Coder-8B-Instruct (entry 245). 8.3B. Q8_0 fits (estimate). MIT; GGUF by unsloth. The card's comparison table lists competitor rows only, so no number of its own was seen.
15. openai/gpt-oss-20b (entry 242). 20.9B MoE. The fit depends on which GGUF quant is used (not checked). Apache-2.0 card. OpenAI's open-weight release, so the GPT-output rule needs a decision first. No benchmark number was found in the card text.

Caveats:
- No open-model DafnyBench leaderboard was found (WebSearch). The 68% in entry 16 is the best result in that paper, and its abstract does not name the model. DafnyPro's 7B and 14B results (entry 14: 68% and 70%) are abstract figures; the release status of those checkpoints was not seen.
- Quantisation evidence for code is thin. The Q4_K_M versus Q8_0 comparisons found were perplexity and task averages from search summaries, with no code pass rates. The measured papers are entries 100 (post-training quantisation for code), 103 (quantised code generation), 104 (llama.cpp quantisations on Llama-3.1-8B) and 106 (GGUF throughput prediction).
- No RTX 4080 llama.cpp measurement for a 30B MoE was found. The nearest measured figure is 57.6 tokens per second for a Qwen3-30B-A3B Q4_K_M on an RX 7900 XTX (forum post, search summary).
- The runtimes for running GGUF builds locally are ggml-org/llama.cpp (entry 175) and unslothai/unsloth (entry 176).
