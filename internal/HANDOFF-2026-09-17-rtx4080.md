Where the MacBook left off, and what the RTX 4080 does next. Read this first, then `t/runs/2026-09-17/README.md` (the copy check correction). Background: `internal/HANDOFF-2026-09-16.md` and `internal/MACHINES.md`.

## Where things stand

- **The goal.** locallm builds models from scratch; t filters what they learn from. The claim to prove: a model built only from filtered data solves more held-out problems per parameter, and is less often wrong while proven, than the same model built from raw data, and than small open models such as Phi-4-mini.
- **The checkers.** All seven run on the lab workstation and on the MacBook, both reproducing the committed matrix (30 of 34). The lab workstation is for CPU work only from now on: grading, sweeps, gates.
- **The free-form loop, corrected.** The copy check kept each task's format version, so exact copies of corpus tasks counted as new. Recounted: at the same data size, a model built from clean data wrote 29 new clean programs of 500 and one built from raw data wrote 1; round 1 of the clean loop reached 31. The MacBook's rerun gave 25. The direction holds, and the effect is about a third smaller than first recorded. Most of those programs are short, loop-free near-copies of corpus tasks, so more free-form rounds will not move the goal.
- **Held out, the number that matters.** Over the 232 held-out problems of `split-v3.json` (from `t/score_heldout.py`):

| Answer set | Tasks | Tests pass | Clean: tests pass and all seven | Proven but wrong: all seven, tests fail |
|---|---|---|---|---|
| Qwen3.8-27B-FP8, temperature 0 (`qwen3.8-27b-fp8-v3`) | 116 | 81 | 12 | 7 |
| Model locallm built from the clean corpus (`locallm-r0`) | 199 | 0 | 0 | 188 |

The 27B's 12 of 232 is the bar a small model has to approach. The locallm-built model recites verified tasks it memorized (151 exact copies), because the clean pool holds only 47 problem examples.

## What the RTX 4080 is for

The pool needs many more problem examples. On this desktop that means:
1. Generate answer sets with a model that fits in 16 GB.
2. Build the clean pool from the answers that pass their tests and verify.
3. Train the small student and build a locallm model on that pool.
4. Score them against Phi-4-mini on the held-out problems.

Grading can run here if the checkers are installed. Otherwise push the answers and grade on the lab workstation.

## 2. Generate answer sets

Ollama serves the API `t/spec_experiment.py` talks to (127.0.0.1:11434). Install it inside WSL so no network setup is needed:

```bash
curl -fsSL https://ollama.com/install.sh | sh
OLLAMA_NUM_PARALLEL=4 ollama serve &          # or run it in its own terminal
ollama pull qwen2.5-coder:14b                  # about 9 GB, 4-bit
```

Eight answer sets over the 649-problem pool: seed 1 at temperature 0 as the reference, seeds 2 to 8 sampled.

```bash
M=qwen2.5-coder:14b
for S in 1 2 3 4 5 6 7 8; do
  T=qwen2.5-coder-14b-v3-s$S; TEMP=0.7; [ $S = 1 ] && TEMP=0
  python3 t/spec_experiment.py generate --model $M --tag $T --pool v3 --prompt v3 --seed $S \
      --temperature $TEMP --num-ctx 8192 --num-predict 3072 --timeout 1800 --jobs 4
  python3 t/spec_experiment.py extract --model $T --pool v3
  python3 t/spec_experiment.py tests   --model $T --pool v3
  python3 t/pool_pick.py t/out/spec-experiment/$T
done
```

`pool_pick.py` copies into `<tag>/grade-in/` only the tasks that pass their tests and are not copies. Those are the only tasks worth checker time.

## Rules that keep the numbers honest

- A number goes in a file only if it was measured, with the command that measured it.
- Clean means all three at once: tests pass, verified in all seven with the broken copy caught, and not a copy of training data.
- Held-out problems never enter a training set. `loop_dataset.py` enforces this through `split-v3.json`, and `split-v3.json` never changes.
- A checker timeout is not a verdict. Re-grade timeouts alone before calling a count final.
- No em-dashes in repository prose.
