# Core modernization and measured scaling, 2026-09-19

**The owned model now has a modern architecture and measured training-step support up to 312M
parameters. Better learned answers have not yet been demonstrated.** The old character-model/checkpoint
path remains available and its legacy forward pass is bit-identical to the pre-change source under the
same seed. This work does not use pretrained weights.

`model.py` adds an explicit `architecture="modern"` configuration: rotary query/key positions,
RMSNorm with float32 reduction, and a SwiGLU feedforward layer. Optional activation checkpointing
recomputes blocks during backward. The original learned-position/LayerNorm/GELU configuration remains
`architecture="gpt"`; missing architecture fields in old checkpoints select that topology.
`total_params()` counts every trainable weight once, while `num_params()` preserves the historical
count that excludes learned positions. Generation can project just the final token's logits.

`train.py` exposes the architecture, recomputation, tokenizer, vocabulary, and three size presets, and
records them in the run ledger. Presets select the modern architecture; commands without a preset keep
the old dimensions and character tokenizer. Medium/large presets enable recomputation by default.
Checkpoints include the tokenizer fingerprint. BPE loss is reported in BPE-token units and is not
compared to the old character n-gram baseline.

## What was run

The predictions were written in [PREREG-core-modern-2026-09-19.md](PREREG-core-modern-2026-09-19.md)
before these checks. All compute ran on the lab workstation. The raw observations, source hashes, and
settings are [core-results-2026-09-19.json](core-results-2026-09-19.json). These measurements precede
the separate KV-cache work; the artifact identifies the exact model source tested.

Eight core tests passed on CUDA: causal prefix invariance, fused/manual attention agreement, legacy
loading, modern save/load behavior and finite gradients, dropout-gradient parity under checkpointing,
rotary norm preservation, RMSNorm at low precision, and final-token projection equivalence. All nine
existing checkpoint tests passed. A separate comparison against `git show HEAD:locallm/model.py`
confirmed identical legacy weights and full-forward logits. CLI preset/default checks also passed.

The matched probe uses six layers, width 512, eight heads, vocabulary 8192, context 512, batch four,
BF16 autocast, three warmups and ten timed forward/backward steps per repeat. Three repeats randomize
variant order. It performs no optimizer updates. Hardware: RTX 6000 Ada; PyTorch 2.13.0+cu130.

| Configuration | Parameters | Median ms/step | Median peak allocated MiB |
|---|---:|---:|---:|
| Original GPT architecture | 23,371,776 | 5.87 | 570.76 |
| Modern architecture | 23,468,544 | 11.16 | 696.03 |
| Modern + activation checkpointing | 23,468,544 | 24.60 | 341.30 |

**The modern core is currently slower:** approximately 1.9 times the original's step time here.
Checkpointing reduces the modern core's measured peak allocation by about 51%, exceeding the
preregistered 20% reduction, while increasing its step time about 2.2 times. This is a capacity tradeoff,
not a training-speed win. The machine is shared; timings characterize these runs rather than an
uncontended hardware ranking. CUDA allocated memory does not include every driver/context allocation.

A native `F.rms_norm` replacement was considered and rejected before benchmarking. Float32 parity
passed, but its BF16 weight gradients exceeded the fixed 0.02 absolute/relative tolerance in three
of 512 entries (maximum absolute difference 0.0381). The production normalization was not changed.

## Actual optimizer steps at the new sizes

The three presets each completed one warmup and three timed AdamW updates at context 2048, batch one,
vocabulary 8192, BF16 autocast, and activation checkpointing. Inputs were random. All losses and gradients
were finite. These checks ran concurrently on separate cards, with each card's available memory checked
first; they are fit/throughput observations, not a controlled speed comparison across sizes.

| Preset | Layers / width / heads | Parameters | ms/update | Peak allocated GiB |
|---|---|---:|---:|---:|
| `core-small` | 8 / 512 / 8 | 29,893,120 | 33.18 | 0.60 |
| `core-medium` | 12 / 768 / 12 | 91,245,312 | 47.84 | 1.52 |
| `core-large` | 24 / 1024 / 16 | 312,001,536 | 117.63 | 4.88 |

The scale-fit prediction held at these exact shapes. Larger batches, vocabularies, and contexts need
their own fit measurements. Four random-input updates do not establish learning stability or quality.

## Use and reproduce

From `locallm/` on the lab workstation, select a card from its current available memory, then:

```sh
python train.py --data corpus.txt --out out/core-medium \
  --preset core-medium --tokenizer bpe --vocab-size 8192 \
  --batch-size 1 --steps 2000 --lr 0.0003
```

This is a concrete starting configuration, not an optimum learning-rate claim. It needs enough distinct
training and validation text for 2048-token windows. BPE uses the optional `tokenizers` dependency in
`requirements-training.txt`; character mode remains available. Explicit layer/head/width/context flags
override a preset. `--no-gradient-checkpointing` can trade memory for throughput when the batch fits.

```sh
LOCALLM_TEST_DEVICE=cuda python test_model_core.py -v
python test_checkpoint.py
python bench_core.py --out matched-core.json
python bench_core.py --variant modern-checkpoint --optimizer-step \
  --layers 24 --heads 16 --width 1024 --context 2048 --batch 1 \
  --warmup 1 --steps 3 --repeats 1 --out scale-large.json
```

Next comes useful learning: train on richer, rights-cleared semantic tasks, freeze family-disjoint
evaluations, and compare multiple seeds at equal compute. Report correct accepted tasks and resource
