# Source-pretraining comparison

The modern architecture reduced final held-out loss by 24.55%, 26.61% and
28.70% across the three matched seeds. All six runs completed without a training
failure. The modern training segments took about 285–286 seconds, versus
241–244 seconds for GPT; stronger token prediction came at higher cost.
The [sanitized machine-readable report](source-pretraining-results-2026-09-19.json)
was generated by [the strict reporter](summarize_pretraining.py).

Descriptive generation remains poor. All 24 post-hoc greedy completions (four
source categories across six checkpoints, 96 new tokens each) showed repetitive
or malformed continuations rather than useful solutions. They were inspected,
not scored as an executable benchmark. [The sampling script](sample_source_study.py)
fixes the prompts for later comparison. Lower loss is not yet useful answering.

The completion watcher detected the terminal event, but its `codex exec resume`
wake failed because the already-open conversation held an active thread writer.
An idle turn does not release that ownership. The repaired watcher uses native
`codex queue --thread ... --message ...` to deliver to that existing writer.
Queue acceptance and actual delivery are distinct; the wake requires an
end-to-end delivery check. Existing failed-wake evidence is preserved.

The ≥20% learning and ≥3% architecture thresholds apply to every planned seed; no repeated result is declared while any pair is missing or invalid.


- This measures BPE token loss, not executable correctness, proof quality, or a Phi win.
- Fixed validation windows are identified by partition/tokenizer hashes, evaluation seed/iterations, rank count, microbatch and context.
- Matching trainer and optimizer source hashes pins unrecorded AdamW and gradient-clipping constants; their values are not independently stored in metadata.
- Finite-loss evidence covers recorded evaluations; completed training relies on the trainer's per-update nonfinite guards.
- Timing and peak memory cover only the final process segment after resume; run order is modern then GPT.
- All planned seeds are displayed; missing, failed and invalid arms are not replaced by a best-seed result.
